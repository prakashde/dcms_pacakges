1. What each package is responsible for

Do not re-implement rule logic in DCMS. The engine owns every formula, Required Keywords rule, validation row, and Submit decision. The React package owns presentation and Workbench state; DCMS owns records, permissions, persistence, and the workflow transaction.

LayerOwnsDoes not own
@dcms/form-rules
0.10.5		 Chevrotain formula and Required Keywords parsing, the controlled Formula.js function registry, validation-row compilation, limits, diagnostics, Record evaluation, canSubmit/canSave, input guidance, dependency analysis. React, DOM, persistence, authentication, workflow state.
@dcms/form-rules-react
0.4.0-parity.6		 FormEditor, RecordForm, RecordField, FieldFeedback, Workbench model conversion, stores, revision/package codecs, draft helpers, async evaluation controllers. Rule semantics, Record persistence, DCMS API shapes, production workflow.
DCMS host Form/Record API rows, permissions, Redux state, Lexical serialization, submit transaction, offline/Dexie storage. Formula parsing or validation decisions.
The one rule that prevents most integration bugs DCMS rows stay in the DCMS shape. Convert to the Workbench model at the boundary, let the engine evaluate, then convert back. Never persist the Workbench model as the API payload.

Install the built tarball. Copying packages/form-rules-react/src into src/ bypasses the package contract, duplicates dependencies, and makes the next update a manual merge. If you need to debug package source, use npm link temporarily and remove it before committing.

Step 2

4. Required app configuration

4.1 Dependencies and the React 18 override

The React adapter declares react@19.3.0 as a peer. DCMS runs React 18. Keep the existing override so npm does not install a second React copy inside the adapter:

"dependencies": {
  "@dcms/form-rules": "file:vendor/dcms-form-rules-0.10.5.tgz",
  "@dcms/form-rules-react": "file:vendor/dcms-form-rules-react-0.4.0-parity.6.tgz"
},
"overrides": {
  "@dcms/form-rules-react": {
    "react": "$react"
  }
}
Do not remove the override Without it, npm may install React 19 under the adapter. Two React copies produce “Invalid hook call” and broken context consumers. The adapter is qualified on React 19.3.0; React 18 is a deliberate host override and must be verified in the app.

4.2 Jest module mapping

CRA's Jest 27 cannot resolve the engine's ESM entry and cannot map the adapter's exports field. Keep this mapping for the engine's Formula.js dependency:

"jest": {
  "moduleNameMapper": {
    "^@formulajs/formulajs$": "<rootDir>/node_modules/@dcms/form-rules/node_modules/@formulajs/formulajs/lib/cjs/index.cjs"
  }
}

Adapter tests must virtual-mock the React package because CRA does not transform ESM inside node_modules:

jest.mock(
  "@dcms/form-rules-react",
  () => ({
    formDefinitionFromWorkbenchModel: (model) => ({
      formId: model.formId,
      version: model.formVersion,

        id: field.id,
        label: field.label,
        valueType: field.valueType,

      }))
    })
  }),
  { virtual: true }
);
Jest is not the integration test The mock keeps adapter unit tests fast. Prove the real package with react-scripts build and a browser scenario; the engine itself is covered by 164 Node tests in the package repository.

Step 3

5. Form authoring with FormEditor

FormEditor is a controlled component. It receives a Workbench model and emits the next model after every accepted authoring action. DCMS stores rows, so the adapter converts in both directions.

5.1 Minimal host component

Simplified from the real src/common/FormBuilder/FormBuilder.js:

import { useMemo } from "react";
import { FormEditor } from "@dcms/form-rules-react";
import {
  rowsFromWorkbenchFormModel,
  validateModelOptions,
  workbenchFormModelFromRows
} from "./dcmsFormAdapter";

export function FormFieldsEditor({ rows, setRows, formId, formVersion }) {
  const model = useMemo(
    () => workbenchFormModelFromRows(rows, { formId, formVersion }),
    [rows, formId, formVersion]
  );

  const handleChange = (nextModel) => {
    const optionError = validateModelOptions(nextModel);
    if (optionError) {
      return { accepted: false, error: optionError };
    }

    try {
      setRows((previousRows) =>
        rowsFromWorkbenchFormModel(nextModel, previousRows)
      );
      return { accepted: true };
    } catch (error) {
      return {
        accepted: false,
        error: error instanceof Error ? error.message : String(error)
      };
    }
  };

  return (
    <FormEditor
      model={model}
      onChange={handleChange}
      onEditingFieldChange={(fieldId) => {
        // Optional: track the row whose authoring draft is open.
      }}
    />
  );
}

5.2 Supported FormEditor props

PropTypeRequiredBehavior
modelWorkbenchFormModelYesMust have schemaVersion: 1, unique field IDs, and a category-compatible valueType.
onChange(model) => { accepted, error? }YesReturn { accepted: false, error } to reject an edit and show the message.
onEditingFieldChange(fieldId | null) => voidNoReports the row whose edit draft is open.
acceptedRecordContextRecord<string, { valueText, validationText, validationState }>NoRead-only Value/validation evidence beside each field.
disabledbooleanNoBlocks opening or applying edits.
disabledReasonstringNoMessage shown while disabled.
Props that are not part of the contract Only the props above are implemented. Unknown props are ignored by JavaScript, so an unsupported callback will silently never fire. Verify against dist/FormEditor.d.ts after each package update.

5.3 Build the read-only evidence columns (optional)

To show the accepted Value and validation status in the editor, build the context from the current rows and pass it in:

import { useMemo } from "react";
import { buildAcceptedRecordContext } from "./dcmsFormAdapter";

const acceptedRecordContext = useMemo(
  () => buildAcceptedRecordContext(rows, model),
  [rows, model]
);

<FormEditor
  model={model}
  onChange={handleChange}
  acceptedRecordContext={acceptedRecordContext}
/>

5.4 What happens on each edit

  1. The author edits a label, category, option, must-be-correct flag, or validation row.
  2. FormEditor emits a new Workbench model.
  3. validateModelOptions enforces DCMS list-field guarantees (non-empty, unique options).
  4. rowsFromWorkbenchFormModel maps the model back to DCMS rows, preserving row _id, form_type names, and API form_type_ref when formTypes is supplied.
  5. Returning { accepted: true } lets the editor close the draft; returning an error keeps the edit open.
Step 4

6. Record rendering and live evaluation

Evaluation needs three inputs: Workbench fields, a value map keyed by field ID, and the engine result. The package does not persist values.

6.1 Full Record surface with RecordForm

import { useMemo, useState } from "react";
import { RecordForm } from "@dcms/form-rules-react";
import {
  evaluateFormRows,
  valuesMapFromRows,
  workbenchFormModelFromRows
} from "./dcmsFormAdapter";

export function RecordSurface({ rows, onSubmit }) {
  const model = useMemo(() => workbenchFormModelFromRows(rows, {}), [rows]);

  // Seed existing values from the DCMS rows; new records start empty.
  const [values, setValues] = useState(() => valuesMapFromRows(rows, model));

  const evaluation = useMemo(
    () => evaluateFormRows(rows, values),
    [rows, values]
  );

  return (
    <>
      <RecordForm
        fields={model.fields}
        values={values}
        evaluation={evaluation}
        onValueChange={(fieldId, value) =>
          setValues((previous) => {
            const next = new Map(previous);
            next.set(fieldId, value);
            return next;
          })
        }
      />

      <button
        type="button"
        disabled={!evaluation?.canSubmit}
        onClick={() => onSubmit(values)}
      >
        Submit
      </button>
    </>
  );
}
Gate Submit on the engine, not on local checks evaluation.canSubmit already accounts for Must Be Correct fields, blocking rows, and evaluation errors. canSave is the separate Draft-save gate. Do not infer eligibility from invalidFieldIds.length.

6.2 Custom layout with RecordField

Use RecordField when DCMS needs its own layout. This is what RulesEvaluatedFormRenderer.js does:

RecordField propMeaning
fieldOne WorkbenchFieldModel; its category selects the input control.
valueSource value: number/string, or an array for Radio/Checkbox. Missing means unfilled.

onFocus, selectedOptional focus/selection styling and guidance targeting.

6.3 Reading feedback

const result = evaluation?.values.get(fieldId);

result.validationState;   // "valid" | "invalid" | "warning" | "blocking" | ...
result.evaluationState;   // "ok" | "error" | ...
result.inputGuidance;     // { display, ... } acceptable-input text
result.failureDetails;    // row-level failure evidence
result.evaluationErrorDetails; // runtime calculation errors

The adapter's acceptedValidationContext(result) turns these states into the short labels used by the DCMS UI (Valid, Invalid — blocking, Invalid — warning, Evaluation error — …).

7. Engine-only use (no React)

For server-side checks, tests, or non-React surfaces, use the engine directly. The engine is the only authority; the React package is optional.

7.1 Compile and evaluate with a Map

import { compileForm, evaluateRecord } from "@dcms/form-rules";

const definition = {
  formId: "temperature",
  version: 1,
  fields: [
    {
      id: "f",
      label: "Temperature F",
      valueType: "number",
      mustBeCorrect: true,
      validationRows: [
        {
          id: "range",
          expression: "(VALUE-32)*5/9",
          criteria: "number_less_than",
          keyword: 105
        }
      ]
    }
  ]
};

const plan = compileForm(definition);
const result = evaluateRecord(plan, new Map([["f", 212]]));

console.log(result.canSubmit);          // true
console.log(result.values.get("f").validationState); // "valid"

7.2 JSON payload contract

If the payload already has the versioned Record shape, use evaluateRecordPayload:

import { compileForm, evaluateRecordPayload } from "@dcms/form-rules";

const plan = compileForm(definition);
const json = evaluateRecordPayload(plan, {
  formId: "temperature",
  formVersion: 1,
  values: { f: 212 }
});

console.log(json.canSubmit, json.fields.f.validationState);

7.3 From DCMS rows

Use the adapter, not a hand-built definition:

import {
  evaluateFormRows,
  workbenchFormModelFromRows
} from "./dcmsFormAdapter";

const model = workbenchFormModelFromRows(rows, {
  formId: form.form_id,
  formVersion: form.version
});

const evaluation = evaluateFormRows(rows, valuesMap);
// evaluation is null when the definition cannot compile; check and log.
evaluateFormRows returns null instead of throwing A malformed definition or incompatible value is logged with [dcmsFormAdapter] rule evaluation unavailable and the UI should fail closed (block Submit), not silently allow it.

8. The adapter contract

src/common/FormBuilder/dcmsFormAdapter.js is the only place that knows both shapes. Keep conversions there; do not spread them across components.

FunctionDirectionUse
workbenchFormModelFromRows(rows, { formId, formVersion })rows → modelBuild the controlled FormEditor/RecordField model.
fieldModelFromRow(row, index)row → fieldOne field; field ID comes from the row _id or index.
rowsFromWorkbenchFormModel(model, previousRows, { formTypes })model → rowsPersist authoring edits; pass form types so form_type_ref resolves.
evaluateFormRows(rows, values)rows + values → evaluationCompile and evaluate; returns null on compilation failure.
valuesMapFromRows(rows, model)rows → MapSeed existing Record values.
evaluationValueForField(field, row)row → valueNormalize legacy scalar selection values into arrays.
dcmsValueFromValueText(category, text)text → valueValue-column entry: Number, Text, Radio/Checkbox comma lists.
acceptedValidationContext(result)evaluation → labelShort validation text/state for the UI.
buildAcceptedRecordContext(rows, model)rows → context mapRead-only Value/status columns for FormEditor.
normalizeRuleReferences(rows, model)rows → rowsResolve FIELD("label") aliases to engine field IDs for evaluation only.
criteriaToValue / criteriaToLabellabel ↔ enumDCMS stores human labels; the engine uses stable enum values.

8.1 Model shape

{
  schemaVersion: 1,
  formId: "form-123",
  formVersion: 1,
  fields: [
    {
      id: "f1",
      category: "Number",          // Radio | Number | Text | Rich Text | Checkbox
      label: "Pressure",
      options: [],
      mustBeCorrect: true,
      valueType: "number",         // Number → number, everything else → string
      validationRows: [
        {
          id: "r1",
          criteria: "number_less_than", // engine enum, not the DCMS label
          keyword: 105,
          expression: "(VALUE-32)*5/9"  // optional
        }
      ],
      unit: "°C"                    // optional
    }
  ]
}

10. Verification checklist

Build and unit level

  • npm ls @dcms/form-rules @dcms/form-rules-react shows the expected versions and no invalid peer.
  • npm run build:clientdev completes without module-resolution errors.
  • CI=true npm test -- --watchAll=false src/common/FormBuilder passes.
  • No console warning about duplicate React or invalid hook calls.

Form Builder scenario

  1. Open a Form page and add a Number field.
  2. Add a validation row with expression (VALUE-32)*5/9, criterion Number Less Than, keyword 105.
  3. Enter Value 212: the row shows Valid and Submit is permitted.
  4. Enter Value 300: the row shows Invalid — blocking and Submit is blocked.
  5. Switch the category to Radio, add options, and confirm option validation rejects duplicates or blanks.
  6. Save and reopen the form: rows, form_type_ref, and rules survive the round trip.

Record/preview scenario

  1. Load an existing Record and confirm values are seeded from the rows.
  2. Type an out-of-range value and confirm per-field feedback and selected-field guidance update.
  3. Clear a Must Be Correct field and confirm Submit stays blocked.
  4. Confirm canSave still permits Draft save when only value validation fails.
Regression test the boundary, not the engine Add adapter tests for rows → model → rows and for the criteria label ↔ enum conversion. The engine already has its own 164 Node tests; duplicating formula tests in Jest adds cost without new coverage.

11. Troubleshooting

SymptomCauseFix
ERESOLVE naming react@19.3.0 Adapter peer vs DCMS React 18. Restore the overrides pin. Confirm with npm ls react that only one React is installed.
“Invalid hook call” or context reads null Two React copies (usually under the adapter). Remove node_modules and reinstall with the override. Check npm ls react for a nested 19.x.
Jest: Cannot use import statement outside a module CRA Jest ignores ESM in node_modules. Use the virtual mock shown in section 4.2; do not add the package to transformIgnorePatterns just for tests.
Jest: cannot resolve @dcms/form-rules-react exports Jest 27 does not understand the package export map. Mock the module in adapter tests. Integration is proved by the CRA build/browser.
formDefinitionFromWorkbenchModel throws “requires valueType …” Category and valueType disagree (e.g., Number + string). Use valueType: "number" for Number; "string" for all other categories. The adapter does this for you.
Throws “Duplicate Workbench field ID” Two DCMS rows resolved to the same field ID. Check row _id/index uniqueness; do not derive IDs from labels.
Rules “not evaluated” and adapter logs a warning The engine rejected the definition (bad criteria, expression, or required keyword). Read the console error; fix the row. Keep Submit blocked when evaluation is null.
Package changes are not visible in the app Same version reinstalled from a cached file: tarball. Bump the package version and reinstall; for a local test use npm install --force, then restart CRA.
Styles missing or visually different Package CSS is not bundled. Import prototypeFormEditor.css / FormRenderer.css; check the form container classes.
Submit allowed with invalid data Host checks instead of evaluation.canSubmit, or evaluation returned null and was ignored. Gate on the engine result and fail closed on null.
Build succeeds but browser shows stale bundle CRA dev server did not pick up a node_modules change. Stop the dev server, reinstall the tarball, run npm start again.
